## 1. Telegram Bot API
- `python-telegram-bot`, long polling (`app.run_polling()`), процесс
  `bot.py` работает напрямую (не под systemd — обычный `python3 bot.py`,
  PID 1288950 на момент проверки).
- Токен: `TELEGRAM_BOT_TOKEN` из `.env`.
- Команды и хендлеры: см. `ARCHITECTURE.md`. Плюс, по git log, теперь
  добавлены: Telegram Live Location (`edited_message`/`handle_location`),
  геозона-детекция (`_is_inside_sector`) с алертами сотруднику и
  диспетчеру, обновление уже отправленных алерт-сообщений через
  `telegram_message_id` (`update_incident_status`).

## 2. Sentinel Hub / Copernicus Data Space Ecosystem (Earth Observation)
Без изменений относительно первой инспекции — OAuth2 client_credentials
(`SENTINEL_CLIENT_ID`/`SENTINEL_CLIENT_SECRET`) → Process API
(`sh.dataspace.copernicus.eu`), синхронный `urllib.request` внутри async
эндпоинтов, RGB + NDVI визуализация Sentinel-2 L2A, 512×512, bbox из
`boundary_json` сектора. См. предыдущую версию документа для деталей
evalscript'ов — этот блок кода не менялся судя по коммитам.

## 3. Anthropic Claude API — OCR лесных планов (⭐ новое, ранее числилось как "модуль отсутствует")

**Файл подтверждён на сервере:** `/root/forest_ai/services/robez_ocr_vision.py`
(33 КБ, последнее изменение 10 июля).

- **Библиотека**: официальный `anthropic` Python SDK
- **Модель**: `claude-sonnet-4-5`
- **Ключ**: `ANTHROPIC_API_KEY` из окружения (падает `RuntimeError`, если не задан)
- **Задача**: читает скан "Robežu Plāns" / "Situācijas plāns" / "Zemes
  robežu plāns" / "Zemes ierīcības projekts" как изображение (base64,
  `image/jpeg|png|webp`) и возвращает структурированный JSON с координатами
  границ участка.
- **Почему заменили Tesseract**: старая `analyze_robez_plan_ocr()` (pytesseract)
  часто возвращала 0 точек — таблицы координат на сканах плохо читаются
  OCR-движком (смешанный латышский/цифровой текст, шум, перекос скана).
  Claude Vision читает изображение напрямую и даёт куда более надёжный результат.
- **Формат ответа сохранён идентичным** старой функции — вызывающему коду
  (`bot.py`/`api.py`) не пришлось меняться.
- **Ключевая функциональность промпта**:
  - Распознаёт координаты в LKS-92 (EPSG:3059), конвертирует в WGS84
    приближённой формулой (та же `lks92_to_wgs84`, что и везде в проекте, ~100м точность)
  - Поддерживает планы БЕЗ полной таблицы координат — геометрическая
    реконструкция по одной referenced-точке + масштабу + указанной площади
  - Multi-sector detection (патч от 2026-07-09): распознаёт не только
    главный контур участка, но и вложенные под-фигуры (здания, ограниченные
    зоны, суб-парцеллы с внутренней разделительной линией) — каждая
    становится отдельным `proposed_sector`
  - Явно помечает low-confidence случаи (референсная координата вне
    диапазона LKS-92 200000–800000 для Латвии) в поле `notes`, чтобы не
    выдавать координаты с неявной низкой точностью за надёжные
- **Риск/стоимость**: каждый вызов = один запрос к Anthropic API с
  изображением — стоит реальных денег и времени за каждый загруженный скан
  плана. Нет упоминания кэширования по хэшу изображения (в отличие от
  ROADMAP-пункта про кэширование AI-рекомендаций Inspector по хэшу issues) —
  стоит уточнить, есть ли защита от повторной обработки одного и того же файла.

Без изменений — опциональная зависимость (`try/except ImportError`),
